# Sesión 2026-05-12 — Fase 3: Historial de Viajes + Detalle con Mapa

## Qué se hizo

### MapAdapter (patrón adaptador para mapas)
- `lib/core/maps/map_adapter.dart` — interface `MapAdapter` con `buildMap({points, height})`
- `lib/core/maps/osm_map_adapter.dart` — implementación flutter_map (OpenStreetMap): polyline naranja sobre la ruta, marcadores de inicio/fin, fit automático a bounds cuando hay ≥2 puntos GPS
- `lib/core/maps/google_map_adapter.dart` — implementación google_maps_flutter: activada con `MAP_PROVIDER=google` en `.env`

### Widgets de presentación
- `lib/features/trips/presentation/widgets/trip_card.dart` — card con origen→destino, chip de estado (color por tipo), fecha, KM y puntos obtenidos
- `lib/features/trips/presentation/widgets/trip_map_view.dart` — selecciona el adapter via `AppConfig.instance.mapProvider`

### Pantallas
- `lib/features/trips/presentation/screens/trips_list_screen.dart` — lista agrupada por mes con `intl DateFormat`, pull-to-refresh que llama directamente a `syncService.syncTrips()` (sin invalidar el StreamProvider para evitar flash de carga), estado vacío
- `lib/features/trips/presentation/screens/trip_detail_screen.dart` — `CustomScrollView` con `SliverAppBar` fijada; secciones: status + calificación + fechas, grid 2×2 de stats (KM/rendimiento/diesel/puntos), mapa GPS (solo si hay puntos), lista de incidencias, lista de alertas de seguridad

### Router
- `lib/core/router/app_router.dart` — nueva pestaña **Viajes** (índice 1 en NavigationBar); `/trips` dentro del `ShellRoute` (muestra nav bar); `/trips/:id` fuera del `ShellRoute` (pantalla completa sin nav bar, accesible via `context.push`)

## Problemas encontrados y soluciones

| Problema | Solución |
|---|---|
| `uri_does_not_exist: 'package:latlong2/latlong2.dart'` | El paquete se llama `latlong2` pero su librería interna es `latlong.dart`. Import correcto: `package:latlong2/latlong.dart` |
| `const Scaffold(...)` con `body: const AppLoadingWidget(...)` | `Scaffold` SÍ tiene constructor `const` en Flutter. El lint `prefer_const_constructors` señalaba que el `Scaffold` entero podía ser `const` ya que todos sus argumentos son const |
